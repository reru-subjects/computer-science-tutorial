## ส่วนที่ 3 คิดเชิงอัลกอริทึมก่อนลงมือเขียนโค้ด

### 3.1 อัลกอริทึมคืออะไร

อัลกอริทึม (Algorithm) หมายถึงลำดับขั้นตอนที่ชัดเจน จำกัด และทำตามได้จริง
เพื่อเปลี่ยนข้อมูลเข้า (Input) ให้กลายเป็นผลลัพธ์ (Output) ที่ต้องการ โดนัลด์ คนูธ
(Donald E. Knuth) กำหนดคุณสมบัติที่อัลกอริทึมต้องมีไว้ 5 ประการ ดังตาราง

| **คุณสมบัติ**                      | **ความหมาย**                     | **ตัวอย่างที่ผิดคุณสมบัตินี้**                   |
|---------------------------------|----------------------------------|----------------------------------------|
| **ความจำกัด (Finiteness)**       | ต้องทำงานจบภายในจำนวนขั้นที่จำกัด      | “ลวกเส้นไปเรื่อย ๆ” โดยไม่บอกว่าเมื่อไรหยุด    |
| **ความชัดเจน (Definiteness)**    | ทุกขั้นตอนต้องตีความได้แบบเดียว ไม่กำกวม | “ใส่น้ำปลาพอประมาณ” ซึ่งแต่ละคนตีความไม่ตรงกัน |
| **ข้อมูลเข้า (Input)**             | มีข้อมูลเข้า 0 ชุดขึ้นไปที่นิยามไว้ชัด       | ไม่ระบุว่าลูกค้าสั่งอะไร แต่สั่งให้เริ่มทำ          |
| **ข้อมูลออก (Output)**            | ต้องให้ผลลัพธ์อย่างน้อย 1 อย่าง         | ทำทุกขั้นตอนแล้วไม่ได้ก๋วยเตี๋ยวออกมา           |
| **ความเป็นไปได้ (Effectiveness)** | แต่ละขั้นต้องทำได้จริงด้วยทรัพยากรที่มี     | “เดาใจลูกค้าว่าอยากกินอะไร”                |

### 3.2 การคิดเชิงคำนวณสี่เสาหลัก

เจนเน็ต วิง (Jeannette Wing) เสนอแนวคิดการคิดเชิงคำนวณ (Computational
Thinking) ไว้ในปี ค.ศ. 2006 ซึ่งกลายเป็นกรอบมาตรฐานของการสอนเขียนโปรแกรมทั่วโลก
ประกอบด้วยสี่เสาหลัก

- **การแตกปัญหา (Decomposition) —** แยก “ระบบสั่งก๋วยเตี๋ยว” ออกเป็นงานย่อย ได้แก่
  รับออเดอร์ จัดคิว คิดเงิน และสรุปยอดขาย

- **การหารูปแบบ (Pattern Recognition) —** สังเกตว่าทุกออเดอร์มีโครงเหมือนกันคือ
  ชื่อเมนู จำนวน และหมายเหตุ จึงเก็บด้วยโครงสร้างเดียวกันได้

- **การคิดเชิงนามธรรม (Abstraction) —** ตัดรายละเอียดที่ไม่เกี่ยว เช่น สีเสื้อลูกค้า
  ออกจากแบบจำลอง เก็บเฉพาะข้อมูลที่ระบบต้องใช้

- **การออกแบบอัลกอริทึม (Algorithm Design) —**
  เรียงขั้นตอนทั้งหมดเป็นลำดับที่คอมพิวเตอร์ทำตามได้

### 3.3 รหัสเทียมและผังงาน

ก่อนเขียนโค้ดจริง ให้เขียนรหัสเทียม (Pseudocode)
ซึ่งเป็นภาษากึ่งมนุษย์กึ่งโปรแกรมที่ไม่ผูกกับภาษาใดภาษาหนึ่ง
ข้อดีคือเราตรวจตรรกะได้โดยไม่ต้องกังวลเรื่องไวยากรณ์
และเมื่อตรรกะถูกแล้วจึงแปลเป็นไพธอนได้ทันที

**รหัสเทียม: สรุปยอดขายของยายนวลในหนึ่งวัน**

```text
เริ่ม
  รับ order_list (รายการออเดอร์ทั้งหมดของวันนี้)
  กำหนด total = 0
  สำหรับ order แต่ละตัวใน order_list
      ถ้า order.status เท่ากับ 'เสิร์ฟแล้ว'
          total = total + order.price
  แสดงค่า total
จบ
```


ผังงาน (Flowchart) ใช้สัญลักษณ์มาตรฐาน ได้แก่ วงรีสำหรับจุดเริ่ม–จบ
สี่เหลี่ยมผืนผ้าสำหรับการประมวลผล สี่เหลี่ยมด้านขนานสำหรับรับ–แสดงข้อมูล
และสี่เหลี่ยมขนมเปียกปูนสำหรับการตัดสินใจ ผังงานเหมาะกับการสื่อสารกับผู้ที่ไม่ใช่โปรแกรมเมอร์
ส่วนรหัสเทียมเหมาะกับการส่งต่อให้เพื่อนร่วมทีมเขียนโค้ด

### 3.4 โครงสร้างควบคุมสามรูปแบบ

โบห์มและยาโคปินี (Böhm และ Jacopini, ค.ศ. 1966)
พิสูจน์ไว้ว่าโปรแกรมทุกโปรแกรมในโลกสร้างได้จากโครงสร้างควบคุมเพียงสามรูปแบบ
นี่คือข่าวดีสำหรับผู้เริ่มต้น เพราะแปลว่าเรามีสิ่งที่ต้องจำน้อยมาก

| **รูปแบบ**               | **ความหมาย**           | **คำสั่งในไพธอน**  |
|-------------------------|------------------------|------------------|
| **ลำดับ (Sequence)**     | ทำทีละบรรทัดจากบนลงล่าง   | คำสั่งที่เขียนเรียงกัน  |

| **การทำซ้ำ (Iteration)** | ทำซ้ำจนกว่าเงื่อนไขจะเปลี่ยน | for / while      |

ในส่วนที่ 3 เราวางลำดับขั้นตอนไว้แล้ว ส่วนนี้จะตอบคำถามถัดไปว่า “แล้วจะเก็บข้อมูลไว้ที่ไหน”
โครงสร้างข้อมูลแต่ละชนิดมีจุดแข็งต่างกัน การเลือกผิดไม่ได้ทำให้โปรแกรมพัง
แต่ทำให้โปรแกรมช้าลงหลายเท่าตัวและแก้ไขต่อได้ยาก

### 4.1 จากข้อมูลดิบสู่ชนิดข้อมูลนามธรรม

ชนิดข้อมูลนามธรรม (Abstract Data Type: ADT) คือการนิยามว่าโครงสร้างหนึ่ง
“ทำอะไรได้บ้าง” โดยยังไม่สนใจว่า “ทำอย่างไร” เช่น คิว (Queue) นิยามว่าเข้าก่อนออกก่อน
ส่วนจะสร้างด้วยอาเรย์หรือลิงก์ลิสต์เป็นเรื่องของการนำไปใช้งานจริง (Implementation)
แนวคิดนี้ช่วยให้เราคิดเป็นระดับ และเป็นสิ่งที่ AI ยังทำแทนเราไม่ได้ดีนัก

### 4.2 ลิสต์และทูเพิล

ลิสต์ (list) คือลำดับของข้อมูลที่แก้ไขได้ (mutable) เข้าถึงสมาชิกด้วยเลขดัชนี (index)
ที่เริ่มนับจาก 0 เหมาะกับข้อมูลที่มีลำดับและเปลี่ยนแปลงตลอดเวลา เช่น คิวออเดอร์ที่เข้ามาเรื่อย
ๆ ส่วนทูเพิล (tuple) มีหน้าตาคล้ายลิสต์แต่แก้ไขไม่ได้ (immutable)
เหมาะกับข้อมูลที่ไม่ควรเปลี่ยน เช่น พิกัดท่าเรือของร้าน

**ตัวอย่างที่ 4.1 ลิสต์และทูเพิลในระบบของตะวัน**

```python
orders = ['ก๋วยเตี๋ยวเรือ', 'เย็นตาโฟ', 'ต้มยำแห้ง']   # list
print(orders[0])        # ก๋วยเตี๋ยวเรือ  (ตัวแรกคือ index 0)
orders.append('บะหมี่หมูแดง')   # เพิ่มท้ายรายการ
orders[1] = 'เย็นตาโฟพิเศษ'     # แก้ไขได้
print(len(orders))      # 4

pier = (16.0538, 103.6531)   # tuple พิกัดท่าเรือ แก้ไขไม่ได้
# pier[0] = 0.0   <-- บรรทัดนี้จะเกิด TypeError
```


### 4.3 ดิกชันนารีและเซต

ดิกชันนารี (dictionary หรือ dict) เก็บข้อมูลเป็นคู่ “คีย์–ค่า” (key–value)
เหมาะกับการเปิดหาข้อมูลจากชื่อโดยตรง เช่น เปิดราคาจากชื่อเมนู
ซึ่งเร็วกว่าการไล่หาทีละรายการมาก ส่วนเซต (set) เก็บสมาชิกที่ไม่ซ้ำกันและไม่สนใจลำดับ
เหมาะกับงานอย่างการรวบรวมรายการวัตถุดิบที่หมด

**ตัวอย่างที่ 4.2 ดิกชันนารีเมนูและเซตวัตถุดิบที่หมด**

```python
menu = {'ก๋วยเตี๋ยวเรือ': 45, 'เย็นตาโฟ': 50, 'ต้มยำแห้ง': 55}
print(menu['เย็นตาโฟ'])        # 50  -> เปิดหาโดยตรง ไม่ต้องไล่ทีละตัว
menu['บะหมี่หมูแดง'] = 50      # เพิ่มเมนูใหม่

for name, price in menu.items():
    print(name, price)

sold_out = {'หมูสับ', 'เลือด', 'หมูสับ'}
print(sold_out)                # {'หมูสับ', 'เลือด'} -> ตัวซ้ำหายไปเอง
```


### 4.4 สแตกและคิว

สแตก (Stack) ทำงานแบบเข้าทีหลังออกก่อน (Last In, First Out: LIFO)
เหมือนชามที่ยายนวลวางซ้อนกันไว้ ชามที่วางทีหลังสุดคือชามที่หยิบออกก่อน
ในโปรแกรมจริงสแตกคือหัวใจของปุ่มย้อนกลับ (undo) และการเรียกฟังก์ชันซ้อนกัน ส่วนคิว
(Queue) ทำงานแบบเข้าก่อนออกก่อน (First In, First Out: FIFO)
ตรงกับกติกาของลูกค้าที่ต่อแถวหน้าเรือพอดี

**ตัวอย่างที่ 4.3 สแตกชามและคิวลูกค้า**

```python
# Stack ด้วย list
bowls = []
bowls.append('ชาม A')   # push
bowls.append('ชาม B')
print(bowls.pop())      # ชาม B  <- ออกก่อนเพราะเข้าทีหลัง (LIFO)

# Queue ด้วย deque (เร็วกว่า list สำหรับการดึงหัวคิว)
from collections import deque
line = deque(['ตะวัน', 'ยายนวล', 'ลูกค้าคนที่ 3'])
line.append('ลูกค้าคนที่ 4')   # ต่อท้ายแถว
print(line.popleft())          # ตะวัน  <- เข้าก่อนออกก่อน (FIFO)
```


> **ข้อควรระวัง**
>
> ลิสต์ทำหน้าที่เป็นคิวได้ด้วยคำสั่ง pop(0)
> แต่การดึงข้อมูลตัวแรกออกจากลิสต์ทำให้สมาชิกที่เหลือต้องเลื่อนตำแหน่งทั้งหมด จึงใช้เวลาแบบ
> O(n)
>
> ในขณะที่ deque ออกแบบมาให้ดึงหัวคิวได้ในเวลา O(1) เมื่อคิวยาวระดับหลักแสน
> ความต่างนี้เห็นชัดมาก
>
> นี่คือตัวอย่างว่าทำไมการรู้จักโครงสร้างข้อมูลหลายชนิดจึงสำคัญกว่าการจำคำสั่งเพียงชุดเดียว

### 5.2 การค้นหาแบบลำดับและแบบทวิภาค

การค้นหาแบบลำดับ (Linear Search) คือการไล่ดูทีละตัวตั้งแต่ต้นจนเจอ
ใช้ได้กับข้อมูลทุกแบบไม่ว่าจะเรียงหรือไม่ ส่วนการค้นหาแบบทวิภาค (Binary Search)
ใช้ได้เฉพาะข้อมูลที่เรียงลำดับแล้ว โดยตัดข้อมูลทิ้งครึ่งหนึ่งในทุกรอบ วิธีคิดเหมือนเกมทายเลข 1
ถึง 1,000 ที่ผู้ทายเริ่มจาก 500 เสมอ

**ตัวอย่างที่ 5.2 ค้นหารหัสสมาชิกหนึ่งล้านรายการ**

```python
def binary_search(sorted_ids, target):
    low, high = 0, len(sorted_ids) - 1
    steps = 0
    while low <= high:
        steps = steps + 1
        mid = (low + high) // 2
        if sorted_ids[mid] == target:
            return mid, steps
        elif sorted_ids[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1, steps

members = list(range(1, 1000001))       # รหัสสมาชิก 1 ถึง 1,000,000
print(binary_search(members, 999999))   # (999998, 20) -> เจอใน 20 รอบ
```


ข้อมูลหนึ่งล้านรายการ การค้นหาแบบลำดับอาจต้องเปรียบเทียบถึง 1,000,000 ครั้ง
ในขณะที่การค้นหาแบบทวิภาคใช้เพียงประมาณ 20 ครั้ง เพราะ 2 ยกกำลัง 20
มีค่ามากกว่าหนึ่งล้านเล็กน้อย
ความต่างระดับห้าหมื่นเท่านี้เกิดจากการเปลี่ยนอัลกอริทึมเพียงอย่างเดียว
ไม่ได้เปลี่ยนเครื่องคอมพิวเตอร์

### 5.3 การเรียงลำดับ

การเรียงลำดับ (Sorting) เป็นเงื่อนไขจำเป็นของการค้นหาแบบทวิภาค
และเป็นงานที่ตะวันต้องใช้เมื่อจะจัดอันดับเมนูขายดีประจำเดือน
อัลกอริทึมพื้นฐานที่ใช้สอนความคิดมีสามแบบ

| **อัลกอริทึม**           | **หลักการ**                                         | **ประสิทธิภาพ**      |
|-----------------------|----------------------------------------------------|--------------------|
| **Bubble Sort**       | เปรียบเทียบคู่ที่ติดกันแล้วสลับ ทำซ้ำจนไม่มีการสลับ              | O(n²)              |
| **Selection Sort**    | หาค่าน้อยที่สุดของส่วนที่เหลือมาวางต่อท้ายส่วนที่เรียงแล้ว         | O(n²)              |
| **Insertion Sort**    | หยิบทีละตัวไปแทรกในตำแหน่งที่ถูกต้อง เหมือนเรียงไพ่ในมือ       | O(n²) กรณีดีที่สุด O(n) |
| **Timsort (ในไพธอน)** | ผสม Merge Sort กับ Insertion Sort ใช้งานผ่าน sorted() | O(n log n)         |

**ตัวอย่างที่ 5.3 เขียนเองเพื่อเข้าใจ
และใช้ของจริงเพื่อทำงาน**

```python
def bubble_sort(data):
n = len(data)
for i in range(n - 1):
for j in range(n - 1 - i):
if data[j] > data[j + 1]:
data[j], data[j + 1] = data[j + 1], data[j] # สลับค่า
return data
best_seller = {'ก๋วยเตี๋ยวเรือ': 320, 'เย็นตาโฟ': 180, 'ต้มยำแห้ง': 254}
rank = sorted(best_seller.items(), key=lambda x: x[1],
reverse=True)
print(rank[0]) # ('ก๋วยเตี๋ยวเรือ', 320) -> เมนูขายดีอันดับหนึ่ง
```


> **ข้อสังเกตสำหรับการทำงานจริง**
>
> นักศึกษาต้องเขียน Bubble Sort
> เองอย่างน้อยหนึ่งครั้งเพื่อเข้าใจกลไกการเปรียบเทียบและการสลับค่า
>
> แต่ในงานจริงให้ใช้ sorted() หรือ list.sort() เสมอ เพราะเป็นการเรียงแบบ
> Timsort ซึ่งเขียนด้วยภาษาซีและรักษาลำดับเดิมของค่าที่เท่ากันไว้ (stable)
>
> ผู้ที่ไม่เคยเขียนเองจะไม่เข้าใจว่าทำไมโค้ดที่ AI เสนอถึงช้า
> เมื่อข้อมูลโตขึ้นสิบเท่า


### 5.4 สัญกรณ์ Big-O

สัญกรณ์ Big-O อธิบายว่าเวลาทำงานของอัลกอริทึมจะเติบโตอย่างไรเมื่อขนาดข้อมูล (n) เพิ่มขึ้น
โดยไม่สนใจค่าคงที่และความเร็วของเครื่อง
จุดประสงค์คือเปรียบเทียบอัลกอริทึมกันเองอย่างเป็นกลาง
ตารางต่อไปนี้แสดงจำนวนรอบการทำงานโดยประมาณเมื่อข้อมูลมี 1,000 รายการ

| **Big-O**      | **ชื่อเรียก**      | **จำนวนรอบเมื่อ n = 1,000** | **ตัวอย่างอัลกอริทึม**               |
|----------------|-----------------|---------------------------|---------------------------------|
| **O(1)**       | คงที่             | 1                         | เปิดราคาจากดิกชันนารี               |
| **O(log n)**   | ลอการิทึม         | ประมาณ 10                 | Binary Search                   |
| **O(n)**       | เชิงเส้น          | 1,000                     | Linear Search, วนลูปหนึ่งชั้น        |
| **O(n log n)** | เชิงเส้นคูณลอการิทึม | ประมาณ 10,000             | Timsort, Merge Sort             |
| **O(n²)**      | กำลังสอง         | 1,000,000                 | Bubble Sort, ลูปซ้อนสองชั้น         |
| **O(2ⁿ)**      | เลขชี้กำลัง        | มากเกินกว่าจะคำนวณไหว       | การไล่ทุกความเป็นไปได้แบบไม่มีการตัดทิ้ง |

### 5.5 เวลาทำงานของคำสั่งที่ใช้บ่อยในไพธอน

ตารางนี้คือเครื่องมือตัดสินใจที่ใช้ได้จริงในทุกงานเขียนโปรแกรม ควรจำให้ได้ก่อนขึ้นบทถัดไป

|-------------------|--------------|--------------|--------------------|

| data.insert(0, x) | list         | O(n)         | ต้องเลื่อนสมาชิกทุกตัว   |
| x in data         | list         | O(n)         | ไล่ตรวจทีละตัว        |

| sorted(data)      | list         | O(n log n)   | Timsort            |

### 6.1 ลำดับการทำงานห้าขั้น: คิด–ถาม–ตรวจ–ทดสอบ–บันทึก

2)  **ถามให้อธิบาย ไม่ใช่ถามเอาคำตอบ (Ask to explain) —** ให้ AI
    อธิบายแนวคิดหรือชี้จุดที่ตรรกะของเราหลุด โดยกำหนดเงื่อนไขว่าห้ามให้โค้ดเต็ม

3)  **ตรวจด้วยตา (Trace) —** ไล่โค้ดทีละบรรทัดด้วยตนเอง หรือใช้ pythontutor.com
    เพื่อดูค่าตัวแปรทุกขั้น ถ้าอธิบายบรรทัดใดไม่ได้ แปลว่ายังใช้โค้ดนั้นไม่ได้

4)  **ทดสอบ (Test) —** สร้างกรณีทดสอบอย่างน้อยสามกรณี ได้แก่ กรณีปกติ กรณีข้อมูลว่าง
    และกรณีขอบ เช่น ออเดอร์ที่ไม่มีในเมนู

5)  **บันทึก (Log) —** กรอกตารางบันทึกการใช้ AI (AI Log) แนบท้ายงานทุกครั้ง
    ระบุสิ่งที่ถาม สิ่งที่ได้ และสิ่งที่แก้เอง

## ส่วนที่ 7 จริยธรรม กฎหมาย และความซื่อสัตย์ทางวิชาการ

งานวิจัยของ Fan และคณะ (2025) ที่ตีพิมพ์ในวารสาร British Journal of Educational
Technology ใช้คำว่า “ความเกียจคร้านเชิงอภิปัญญา” (metacognitive laziness)
อธิบายพฤติกรรมของผู้เรียนที่ยกภาระการวางแผนและการตรวจสอบตนเองให้ AI ทำแทน
ผลคือคะแนนชิ้นงานดีขึ้นในระยะสั้น แต่ความสามารถในการแก้ปัญหาด้วยตนเองไม่พัฒนา
วงการศึกษาคอมพิวเตอร์เรียกภาวะนี้อีกชื่อว่า “หนี้ทางญาณวิทยา” (epistemic debt)
คือได้ผลงานมาก่อน แล้วค่อยจ่ายคืนด้วยความไม่เข้าใจในภายหลัง

ข้อตกลงการใช้ AI ในรายวิชานี้จึงกำหนดไว้ดังนี้

- อนุญาตให้ใช้ AI เพื่ออธิบายแนวคิด ตรวจหาข้อผิดพลาด และออกแบบกรณีทดสอบ

- ไม่อนุญาตให้ส่งโค้ดที่ AI เขียนให้ทั้งหมดโดยที่นักศึกษาอธิบายไม่ได้
  ถือเป็นการทุจริตทางวิชาการ

- ทุกชิ้นงานต้องแนบ AI Log
  และนักศึกษาต้องพร้อมตอบคำถามปากเปล่าเกี่ยวกับโค้ดของตนทุกบรรทัด (Code Review
  Interview)

- ต้องตรวจสอบชื่อไลบรารีที่ AI แนะนำเสมอ เพราะมีกรณีที่ AI
  แต่งชื่อแพ็กเกจที่ไม่มีอยู่จริงขึ้นมา (package hallucination)
  ซึ่งกลายเป็นช่องทางโจมตีทางไซเบอร์

- โค้ดที่นำมาจากแหล่งอื่น ไม่ว่าจากเว็บไซต์หรือจาก AI ต้องระบุที่มาในคอมเมนต์เหนือบรรทัดนั้น

> **แบบฟอร์ม AI Log ที่ใช้แนบท้ายงาน**
>
> 1) ข้อความสั่งที่ใช้ (คัดลอกมาทั้งข้อความ) 2) เครื่องมือและวันที่
>
> 3) สิ่งที่ AI ตอบ (สรุปย่อ) 4) สิ่งที่นักศึกษาแก้ไขหรือปฏิเสธ พร้อมเหตุผล

> 5) ข้อความรับรอง: “ข้าพเจ้าเข้าใจโค้ดทุกบรรทัดที่ส่ง และพร้อมอธิบายด้วยวาจา”
> พร้อมลายมือชื่อ

## ส่วนที่ 9 แบบฝึกหัดและคำถามท้ายบท

1)  จงอธิบายความแตกต่างระหว่างโครงสร้างข้อมูลกับอัลกอริทึม
    พร้อมยกตัวอย่างจากร้านของยายนวลอย่างละหนึ่งตัวอย่าง

> **แนวตอบ:** โครงสร้างข้อมูลคือวิธีจัดเก็บ เช่น เก็บเมนูและราคาไว้ในดิกชันนารี
> ส่วนอัลกอริทึมคือลำดับขั้นตอนการทำงานกับข้อมูลนั้น เช่น ขั้นตอนการคำนวณยอดขายรวมของวัน
> ทั้งสองต้องทำงานคู่กันจึงจะเกิดเป็นโปรแกรม

2)  เพราะเหตุใดการใช้ x in menu เมื่อ menu เป็นดิกชันนารี จึงเร็วกว่าเมื่อ menu
    เป็นลิสต์

> **แนวตอบ:** ดิกชันนารีใช้การแฮชคีย์เพื่อคำนวณตำแหน่งโดยตรง จึงใช้เวลา O(1)
> โดยเฉลี่ย ขณะที่ลิสต์ต้องไล่เปรียบเทียบทีละสมาชิกจนกว่าจะเจอ จึงเป็น O(n)

3)  ข้อมูลชุดหนึ่งมี 1,024 รายการเรียงลำดับแล้ว
    การค้นหาแบบทวิภาคจะใช้จำนวนรอบมากที่สุดกี่รอบ จงแสดงวิธีคิด

> **แนวตอบ:** ทุกรอบตัดข้อมูลเหลือครึ่งหนึ่ง จึงเป็น log ฐานสองของ 1,024 ซึ่งเท่ากับ 10
> คำตอบคือไม่เกิน 10 รอบ (ในทางปฏิบัติอาจนับเป็น 11 รอบเมื่อรวมรอบที่ยืนยันว่าไม่พบ)

4)  ตะวันต้องเก็บ “รายชื่อวัตถุดิบที่หมดวันนี้” โดยไม่ต้องการให้มีชื่อซ้ำ
    ควรเลือกโครงสร้างข้อมูลใด เพราะเหตุใด

> **แนวตอบ:** เลือกเซต (set) เพราะตัดสมาชิกซ้ำให้อัตโนมัติ
> และตรวจสอบการมีอยู่ของสมาชิกได้ในเวลา O(1) โดยเฉลี่ย ลำดับของข้อมูลไม่สำคัญในงานนี้

5)  จงอธิบายว่าเหตุใดคิวลูกค้าหน้าเรือจึงควรใช้ deque แทน list
    และความต่างนี้จะเห็นชัดเมื่อใด

> **แนวตอบ:** การดึงหัวคิวจากลิสต์ด้วย pop(0) ทำให้สมาชิกที่เหลือต้องเลื่อนตำแหน่งทั้งหมด
> จึงเป็น O(n) ส่วน deque ทำได้ในเวลา O(1) ความต่างเห็นชัดเมื่อคิวยาวมาก เช่น
> หลักหมื่นหรือหลักแสนรายการ

6)  ฟังก์ชัน bubble_sort ในตัวอย่างที่ 5.3 มีลูป for ซ้อนกันสองชั้นบนข้อมูล n รายการ
    จงระบุ Big-O และประมาณจำนวนรอบเมื่อ n เท่ากับ 2,000

> **แนวตอบ:** เป็น O(n²) จำนวนรอบประมาณ 4,000,000 รอบ
> ซึ่งหมายความว่าเมื่อข้อมูลเพิ่มเป็นสองเท่า งานจะเพิ่มขึ้นประมาณสี่เท่า

7)  AI เสนอโค้ดที่ใช้ Bubble Sort เรียงข้อมูลหนึ่งแสนรายการ นักศึกษาควรตอบกลับอย่างไร
    และควรแก้เป็นอะไร

> **แนวตอบ:** ควรปฏิเสธข้อเสนอนั้น เพราะ Bubble Sort เป็น O(n²)
> ซึ่งเท่ากับหนึ่งหมื่นล้านรอบโดยประมาณ ควรเปลี่ยนไปใช้ sorted() ที่เป็น Timsort ระดับ
> O(n log n) และบันทึกเหตุผลของการปฏิเสธลงใน AI Log

8)  จงยกตัวอย่างสถานการณ์ในระบบของตะวันที่ต้องใช้สแตก
    และอธิบายว่าเหตุใดคิวจึงใช้แทนไม่ได้

> **แนวตอบ:** ปุ่มย้อนกลับการแก้ไขออเดอร์ต้องใช้สแตก
> เพราะการแก้ไขครั้งล่าสุดต้องถูกย้อนก่อน (LIFO) หากใช้คิวซึ่งเป็น FIFO
> ระบบจะย้อนการแก้ไขครั้งแรกสุดแทน ซึ่งผิดความคาดหมายของผู้ใช้

### 11.2 หมายเหตุสำหรับอาจารย์ผู้สอน

- ควรใช้เวลาบรรยายส่วนที่ 3 และ 4 ไม่เกิน 60 นาที แล้วเข้าสู่กิจกรรมเร็วที่สุด
  เพราะผู้เริ่มต้นเข้าใจ O(1) กับ O(n) จากการเดินและนับก้าวได้ดีกว่าการฟังคำอธิบาย

- กิจกรรมที่ 2 และ 3 ทำได้โดยไม่ต้องใช้คอมพิวเตอร์
  เหมาะกับคาบแรกที่ห้องปฏิบัติการยังไม่พร้อม

- ควรประกาศตั้งแต่คาบแรกว่าการสอบปลายภาคมีส่วนที่ต้องเขียนรหัสเทียมด้วยลายมือโดยไม่ใช้เครื่องมือใด
  ๆ เพื่อให้นักศึกษาให้น้ำหนักกับขั้นคิดเอง

- ตรวจสอบเวอร์ชันไพธอนในห้องปฏิบัติการก่อนเปิดภาคเรียน ควรเป็น 3.12 ขึ้นไป เนื่องจาก
  Python 3.10 จะสิ้นสุดการสนับสนุนในวันที่ 31 ตุลาคม 2026

- บทถัดไปจะต่อยอดจากฟังก์ชันค้นหาและจัดคิวในบทนี้ ไปสู่การอ่านและเขียนไฟล์ข้อมูล
  รวมถึงการจัดการข้อผิดพลาดด้วย try/except
